# Analytics API (js/analytics/*)

All functions are pure (no DOM, no network, no Date.now() except via `dv.today()`), work in browser and Node, and return `null` for unknown values rather than 0. Every function that accepts `dv` takes the DataView from `js/analytics/dataview.js`. Heavy results should be memoized with `dv.memo(key, fn)` (auto-invalidated when the store changes). Times of day are expressed as **minutes after local midnight** (`bedtimeMin` may exceed 1440 for after-midnight bedtimes). Weights in lb, nutrition in g/mg/kcal.

Import everything from `js/analytics/index.js`. `adherence` exists in both nutrition.js and protocols.js, so the index exports them as `nutritionAdherence` / `protocolAdherence` (also available as `nutrition.adherence` / `protocols.adherence` namespaces). Returned arrays/objects may be memoized — treat them as read-only.

## dataview.js (additions — existing accessors unchanged)
`makeDataView(store, { tz, today })` — `today` (optional `'YYYY-MM-DD'` or `() => string`) pins "today" for tests/replays; without it `dv.today()` behaves as before.
Additive accessors: `dv.asOf()` (dv.today() memoized per store version — analytics use this; call `dv.invalidate()` when the date rolls over without a store change), `dv.setting(id)` (memoized `store.setting`), `dv.clock(iso, offset?)` → `{ymd, min}`, `dv.minutesAfter(iso, refDate, offset?)`, `dv.sleepClock(date)` → `{bedMin, wakeMin}` (night that ended on `date`), `dv.intake(date)` → `{count, analyzed, pending, failed, lowConfidence, complete, totals, meals, records, firstMin, lastMin, firstAt, lastAt}` (`complete` = ≥1 analyzed meal and none unanalyzed), `dv.planSummary(date)` → `{blocks, plannedMin, doneMin, adherence, byCategory}`, `dv.hasCalendar()`, `dv.eventBlocks(date)` → `[{id, title, start, end}]` (minutes; non-FORGE, non-all-day, non-cancelled/declined), `dv.eventLoad(date)` (see `calendarLoad`; null when no calendar is connected), `dv.dailyWeights()` → one `{date, at, weightLb, source}` per day (first weigh-in; Apple Health weight as fallback), `dv.weightOn(date)`, `dv.deepWorkH(date)` (day log `deepWorkH`, else done/partial `deep` plan blocks once any deep block was marked).
Pure helpers: `localClock(iso, zone, offset?)`, `minutesAfter(iso, refDate, zone, offset?)`, `mergeIntervals(list)`, `freeGaps(busy, from, to)`, `formatNumber(n, dp)` (fast en-US formatting), `dayNum(date)`, `dowOf(date)` (Mon=0), `daysBetween(a, b)`, `WORK_START`/`WORK_END` (480/1080). ISO instants: a record `tz` offset (WHOOP) converts the instant; otherwise an explicit numeric offset is read as recorded (its wall clock is local), `Z` is converted to the DataView zone, no offset = local.

## stats.js
`mean(arr)`, `median(arr)`, `sd(arr)` (sample), `quantile(arr, q)`, `ewma(values, alpha)` → array (nulls carried), `linreg(xs, ys)` → `{slope, intercept, r2, n}`, `pearson(xs, ys)`, `spearman(xs, ys)`, `welch(a, b)` → `{diff, t, df, p}`, `mannWhitney(a, b)` → `{u, p}`, `normalCdf(z)`, `tCdf(t, df)`, `fisherCI(r, n, level=0.95)` → `[lo, hi]`, `benjaminiHochberg(pvals)` → q-values (same order), `zscore(x, m, s)`, `rolling(values, window, fn)`. All ignore null/NaN pairwise.
- `welch.diff` = mean(a) − mean(b). `mannWhitney.u` = U of sample `a`; p is two-sided (normal approximation, tie + continuity correction). `tCdf` uses the regularized incomplete beta function. `rolling` applies `fn` (default mean) to the finite values in each trailing window (null when none). `linreg` always returns the object (fields null when n < 2).
- Also exported: `sum`, `variance`, `pairs`, `ranks` (average ranks), `corrP(r, n)` (two-sided t-approximation), `cohensD(a, b)`, `tTwoSided(t, df)`, `incompleteBeta(x, a, b)`, `lnGamma`, `normalQuantile(p)`.

## daily.js
`buildDaily(dv, from, to)` → `DailyRow[]` (one row per date inclusive, memoized). `dailyRow(dv, date)` → one row.

DailyRow fields (null when unknown): `date, dow, isWeekend, recovery, hrv, rhr, spo2, skinTempC, respRate, calibrating, sleepMin, sleepNeedMin, sleepPerf, sleepEff, sleepConsistency, deepMin, remMin, lightMin, awakeMin, disturbances, bedtimeMin, wakeMin, dayStrain, kcalBurned, steps, avgHr, workoutCount, workoutStrain, workoutMin, lastWorkoutEndMin, trainedStrength, trainedCardio, sessionSets, sessionVolumeLb, sessionMin, kcalIn, proteinG, carbsG, fatG, fiberG, sodiumMg, mealsCount, firstMealMin, lastMealMin, lastMealToBedMin, caffeineLastMin, alcohol, deepWorkH, energy, mood, stress, appetite, soreness, dayRating, meetingMin, meetingCount, afterHoursMeetingMin, longestFreeBlockMin, planMin, planDoneMin, planAdherence, executionScore, requiredDone, requiredTotal, perfect, weightLb, weightTrendLb, peptideDoseMg, daysSinceDose, supplementAdherence, nextSleepMin, nextRecovery, nextHrv, nextRhr, nextSleepPerf, nextEnergy`.

- The sleep on date D is the night that **ended** on the morning of D. `bedtimeMin` for D = minutes after midnight of D−1 (so 23:30 → 1410, 00:30 → 1470). `lastMealToBedMin` for D = bedtime of the sleep that starts the night of D (i.e. `dv.sleep(D+1)`) − `lastMealMin` of D.
- `meetingMin` counts `dv.events(date)` (non-FORGE, non-all-day, accepted); after-hours = outside 08:00–18:00.
- `planAdherence` = done minutes (done = full, partial = 50%) / planned minutes × 100, only when the day has blocks and is in the past or today.
- `daysSinceDose` uses active `peptide` items only; `peptideDoseMg` sums doses of peptide items that day.
- Details: `DAILY_FIELDS` exports the field list in this order. Sleep fields come from the main (non-nap) sleep; bed/wake prefer WHOOP's local `bedtime`/`wake` strings. `kcalIn`…`sodiumMg` are null unless the day's intake is `complete` (a meal still analyzing or failed makes that day unknown, not low); `mealsCount` is null when nothing was logged. `firstMealMin`/`lastMealMin` are relative to midnight of D (a 00:30 snack logged on D → 1470); a negative `lastMealToBedMin` is null. `caffeineLastMin` treats `caffeineLastAt` before 04:00 as after midnight (+1440). `meetingMin` is the union of event time (overlaps not double counted), `longestFreeBlockMin` is within 08:00–18:00, and all meeting fields are null when no calendar is connected. `workoutCount` = WHOOP workouts + app sessions not linked to one; `workoutStrain` = max workout strain; `workoutMin` = union of workout/session intervals; training fields are false/0 (not null) on days with any tracking (WHOOP cycle, workout, session or day log). `deepWorkH` = `dv.deepWorkH(date)`. `requiredDone`/`requiredTotal` are null for future dates. `weightLb` = first weigh-in of the day; `weightTrendLb` carries up to 14 days past the last weigh-in. `peptideDoseMg` converts mcg/µg/g to mg, is 0 when peptide items exist but none was taken and null without peptide items; "active" = in use on that date (between `startedAt` and `endedAt`). `supplementAdherence` = % of due `supplement` items taken that day.

## readiness.js
`baselines(daily, date, window=30)` → `{ hrv, rhr, sleepMin, recovery, respRate, skinTempC }` each `{mean, sd, n}` from the `window` days **before** `date`.

`readiness(dv, date)` →
```js
{ date, status: 'ok'|'calibrating'|'no-data', band: 'green'|'yellow'|'red'|null, score,
  metrics: { recovery, hrv, hrvBase, hrvZ, rhr, rhrBase, rhrZ, sleepMin, sleepNeedMin, sleepDebtMin, sleepPerf, respRate, respDelta, skinTempDelta },
  drivers: [{ key, label, value, text, impact: 'positive'|'negative'|'neutral', weight }],
  training: { mode: 'push'|'build'|'maintain'|'recover', label, detail, strainTarget: [lo, hi] },
  focus: { start: 'HH:MM', end: 'HH:MM', note },
  flags: [{ level: 'info'|'warn'|'alert', text }],
  summary }
```
Band: WHOOP recovery ≥67 green, 34–66 yellow, ≤33 red; without WHOOP use a composite from HRV/RHR z-scores and sleep vs need. Illness flag when respiratory rate ≥ +1.0 br/min over baseline AND (skin temp ≥ +0.5 °C OR HRV z ≤ −1.5). `focus` = first 90–150 min block starting ~60–90 min after wake that does not collide with calendar events.
- `date` defaults to `dv.asOf()`. Extra fields: `scoreSource: 'whoop'|'composite'|null`, `drivers[].phrase` (short phrase used in `summary`). z-scores need ≥ 7 baseline days, otherwise `status: 'calibrating'` (WHOOP recovery still sets the band; also calibrating while WHOOP says so). Composite score = 50 + 20 × weighted mean of (HRV z, −RHR z × 0.6, (sleep/need − 1)/0.1 × 0.6), clamped 0–100. Modes: green + sleep ≥ 90% of need → push [14, 18]; green otherwise or yellow ≥ 50 → build [11, 14]; yellow < 50 → maintain [8, 11]; red or illness → recover [0, 8]; no score → build. `sleepDebtMin` = WHOOP `needDebtMin`, else the 3-night shortfall vs need. Driver keys: `hrv, rhr, sleep, sleepDebt, priorStrain, alcohol, lateMeal, daysSinceDose` (the dose driver only appears when the last 90 days show a difference for the current days-since-dose group: Welch p < 0.1 and |d| ≥ 0.4). `focus` is `{start: null, end: null, note}` when no 90-min window is free; it is 90 min on red days.

## execution.js
`evaluateStandard(dv, standard, date)` → `{ standard, applicable, value, display, done: true|false|null, source: 'manual'|'auto'|'none', target }`. Manual check records override auto. Boolean `true` from legacy checks counts as done for any kind. Target value `'target'` resolves from settings (`whoop.wake` → targets.wake, `day.deepWork` → targets.deepWorkTargetH, `nutrition.protein` → calorieTargets().proteinG, `nutrition.kcal` → calorieTargets().kcal). Auto sources: see docs/ARCHITECTURE.md §8; `avoid` kind is done when the thing did NOT happen (manual check `true` means avoided).
`dayExecution(dv, date)` → `{ date, score, items, required: {done, total}, perfect, pending }` — score = Σweight(done)/Σweight(known) × 100.
`streaks(dv, until)` → `{ current, longest, lastPerfect }` (perfect-day streaks).
`adherenceByStandard(dv, from, to)` → `[{ standard, applicableDays, doneDays, rate }]`.
- Extra field `status: 'done'|'missed'|'pending'|'unknown'|'na'|'future'`. `target` is the resolved `{op, value, unit}` (also `whoop.sleep` → targets.sleepTargetH, `day.caffeineCutoff` → targets.caffeineCutoff). A standard applies on its `days` (Mon=0; an empty array means never), on/after `effectiveFrom`, while active. Future dates → `done: null`, `status: 'future'`. Today: anything not yet known or not yet reached by a source that can still grow (plan, training, nutrition, protocol, deep work) is `pending` (`done: null`), never `missed`. Past days: a manual-only standard without a check is `missed` if the day was opened (day log or any check), else unknown. Check records with `source: 'auto'` are used only when the live source has no value. `protocol.stack`/`protocol.item` with nothing due → `status: 'na'`. Stack names match case-insensitively. `nutrition.item` is unknown while meals are still being analyzed. `time` kind compares minutes; against an evening target (≥ 18:00) values before noon count as after midnight. `display` is a short string ('06:42', '3.5 h', '152 g', '91%', 'Done', 'Avoided', 'Not logged', '—').
- `dayExecution.pending` = number of pending items; `perfect` = all required items done (null for future dates, days without required standards, and today while a required item is pending). `streaks(dv, until = dv.asOf())`: days with `perfect === null` neither extend nor break a streak. `adherenceByStandard` also returns `knownDays`; `rate` = doneDays / knownDays × 100 over dates ≤ today.
- Also exported: `isApplicable(standard, date)`, `autoValue(dv, source, date)`, `resolveTarget(dv, standard, date)`.

## body.js
`weightTrend(weighIns, {alpha=0.1})` → `[{date, weightLb, trendLb}]` for every day first→last weigh-in.
`rateLbPerWeek(series, days=28)` → slope of trend × 7 (null if < 7 points).
`estimateTdee(dv, date, {window=28, minDays=14})` → `{ tdee, method: 'energy-balance'|'insufficient', n, intakeAvg, trendDeltaLb, confidence }` using 3500 kcal/lb.
`calorieTargets(dv, date)` → `{ kcal, proteinG, fatG, carbsG, fiberG, basis: 'manual'|'adaptive'|'estimate', tdee, rationale }` (adaptive: TDEE + surplus toward goal rate; estimate: Mifflin-St Jeor × 1.55 when TDEE unknown; protein = proteinPerLb × current trend weight).
`goalProjection(dv)` → `{ currentTrendLb, goalLow, goalHigh, ratePerWeek, etaDate, weeksToGoal, onTrack, note }`.
`bodySummary(dv, date)` → `{ weight, trend, change7, change28, rate28, tdee, targets, projection, series }`.
- `weightTrend` uses the first weigh-in of each day; days without one carry the trend. `rateLbPerWeek` counts actual weigh-ins in the last `days` entries.
- `estimateTdee` uses the `window` complete days **before** `date` (the in-progress day never counts): TDEE = mean kcal of days with a complete intake log − slope × 3500, where slope = OLS trend (lb/day) of the weigh-ins in the same window (no EWMA lag); `trendDeltaLb` = slope × window. Needs ≥ `minDays` logged days and ≥ 10 weigh-ins. `confidence` `'high'` (≥ 21 days, ≥ 16 weigh-ins, ≥ 75% logged) | `'medium'` | `'low'` (also when the result is outside 1,200–6,000); extra fields `weighIns, window, from, to, note`. Rounded to 10 kcal.
- `calorieTargets`: `manual` needs `targets.kcal` (else it falls back to adaptive/estimate); protein = `targets.proteinG` in manual mode, else proteinPerLb × trend weight rounded to 5 g. Surplus: once the trend reaches `goalWeightLow` → 0 (maintenance; no automatic deficit above the range); else `goalRateLbWk × 3500 / 7` clamped 100–700 when the rate is > 0; else `targets.surplusKcal`. Fat = fatPct of kcal; carbs = remainder (≥ 0). kcal rounded to 10. Extra fields `surplus, weightLb, tdeeInfo`. All null (with a rationale saying what to add) when nothing is known.
- `goalProjection(dv, date = dv.asOf())` also returns `goalRate`; `onTrack` = 28-day rate ≥ 75% of `goalRateLbWk` while below the range, true inside it, null above it or without data; `etaDate` null beyond two years.
- `bodySummary`: `weight` = latest weigh-in (number, plus `weightDate`); `trend` = trend on `date`; changes are trend differences; `series` = trend series up to `date`.
- Also exported: `trendSeries(dv)`, `trendAt(dv, date, maxCarry=14)`, `mifflinStJeor({weightLb, heightIn, age, sex})`.

## strength.js
`e1rm(w, reps)` (Epley; reps 1–12 else null). `exerciseHistory(dv, exerciseId)` → `[{date, sessionId, bestSet:{w,reps}, e1rm, volume, sets, topW}]`. `lastPerformance(dv, exerciseId, beforeDate)` → `{date, sets}|null`. `prs(dv, {since})` → `[{date, sessionId, exerciseId, type:'e1rm'|'weight'|'reps', value, prev}]`. `weeklyMuscleVolume(dv, from, to)` → `[{week, muscle, hardSets, volumeLb}]` (primary muscle 1 set, secondary 0.5). `progression(history, {weeks=8})` → `{slopePctPerWeek, status:'progressing'|'plateau'|'regressing'|'insufficient', n}`. `strengthSummary(dv, date)` → `{ topLifts:[{exerciseId, name, e1rm, change28Pct, status}], recentPrs, weeklySets, sessions28 }`. `cardioHistory(dv, exerciseId?)` → `[{date, exerciseId, durationMin, avgWatts, avgHr, efficiency, distanceMi, kcal}]`.
- Working sets (kind `'work'`, missing or `'working'`, plus `'drop'` and `'failure'` sets; never `'warmup'`; `done !== false`) drive everything; `e1rm(w, 1)` = w; values rounded to 0.1. `exerciseHistory` also returns `maxReps`; bodyweight work at 0 lb has `e1rm: null` and `bestSet` = most reps. `lastPerformance` returns every done set (all kinds) plus `sessionId`. `prs` is chronological (oldest first); an exercise's first session is its baseline; loaded work reports `e1rm` and `weight` PRs, 0-lb bodyweight work reports `reps`. `week` = Monday date `'YYYY-MM-DD'`; secondary muscles also get 50% of the volume. `progression`: e1RM (or best reps for bodyweight) regressed over the last `weeks` weeks of history; ±0.5 %/week thresholds; needs ≥ 3 sessions spanning ≥ 14 days. `strengthSummary(dv, date = dv.asOf())`: up to 6 most-trained strength exercises in the last 8 weeks, `e1rm` = best e1RM in the last 28 days, `change28Pct` vs the 28 days before (extra `metric: 'e1rm'|'reps'`, `best`, `sessions`); `recentPrs` = last 28 days, newest first (max 10); `weeklySets` = `[{muscle, hardSets, avg4}]` for the current week vs the previous 4-week average. `efficiency` = avg watts per avg bpm.

## nutrition.js
`sumNutrients(itemsOrMeals)` → Nutrients. `dayNutrition(dv, date)` → `{ totals, mealCount, targets, remaining:{kcal, proteinG}, pct:{kcal, protein}, proteinPerMeal:[{mealId, at, protein}], firstMealAt, lastMealAt, lastMealToBedMin, flags:[{level, text}] }`. `adherence(dv, from, to)` → `{ days, kcalHitRate, proteinHitRate, avgKcal, avgProtein, avgVsTarget }` (kcal hit = within ±10%, protein hit = ≥95%). `microSummary(dv, from, to)` → `[{key, label, avg, unit, reference, pct}]` (adult-male reference intakes for fiber, sodium (limit), potassium, calcium, iron, magnesium, vitC, vitD).
- `sumNutrients`: a meal contributes its `totals`, else its items; keys with no data are null. `dayNutrition` totals include every analyzed meal (partial while meals are pending); extra fields `complete, pending`; `at`, `firstMealAt`, `lastMealAt` are local `'HH:MM'`; `proteinPerMeal[].slot` added; `remaining` = target − eaten so far (negative = over); `lastMealToBedMin` uses the following night's bedtime. Flags: failed/pending analysis, low-confidence estimates, last meal after `targets.lastMealBy`, last meal < 2 h before bed, and — for complete past days only — kcal < 90% / > 115% of target and protein < 95%.
- `adherence` counts only complete past days; rates are percentages (0–100); `avgVsTarget` = mean (kcal − target) per day (negative = under); extra `avgProteinVsTarget, kcalHits, proteinHits`.
- `microSummary` uses `MICRO_REFERENCES` (general adult references: male = fiber 38 g, sodium ≤ 2300 mg, potassium 3400, calcium 1000, iron 8, magnesium 420 mg, vitamin C 90 mg, vitamin D 600 IU; female references when `profile.sex === 'female'`); extra `limit` (sodium), `days`, `referenceNote`.

## protocols.js
`dueItems(dv, date)` → `[{ item, due, doses }]`. `stackStatus(dv, date, stack)` → `{ stack, items:[{item, taken}], complete }`. `adherence(dv, from, to)` → `[{ item, scheduled, taken, rate }]`. `nextDue(dv, item, today)` → date|null. `doseCycle(dv, itemId, {from, to})` → `{ byDay:[{daysSince, n, appetite, kcalIn, proteinG, hrv, rhr, recovery, sleepMin}], weeklyTotals:[{week, amount, unit}], lastDose, nextDue, n }`.
- Due: `daily` every day; `days` on listed weekdays (Mon=0); `weekly` on listed weekdays, else once per Mon-start week (due until a dose is logged that week, including that day); `asneeded` never. Items count only between `startedAt` and `endedAt`; inactive items without `endedAt` are ignored. Skipped doses never count as taken. `dueItems` includes every item in use that day, with extra `taken`. `stackStatus.complete` is null when nothing in the stack is due.
- `adherence`: future dates excluded; today counts only once taken; once-a-week items count weeks (complete weeks, or any week with a dose); as-needed items report `scheduled: 0` and the days taken. `rate` is a percentage. `nextDue(dv, item|itemId, today = dv.asOf())`.
- `doseCycle` (default window: last 90 days to today): same-day metrics (definitions as DailyRow; intake only for complete past days) grouped by days since the last taken dose of **that** item (0–6); `weeklyTotals` per Monday week in the item's unit with `target` from `weeklyTarget`; extra `item: {id, label (neutralLabel or name), kind}`, `from`, `to`.
- Also exported: `inWindow, isDue, doseDates, takenOn, lastDoseOnOrBefore, toMg, daysSinceDose, doseMgOn, kindAdherenceOn`.

## labs.js
`MARKERS` catalog `{ key: { name, unit, aliases[], category, lowerIsBetter } }`. `normalizeMarkerName(name)` → key|null. `markerSeries(dv, key)` → `[{date, value, unit, flag, refLow, refHigh}]`. `panelFlags(panel)` → out-of-range markers. `labSummary(dv)` → `{ latest, flagged, changes:[{key, name, from, to, pct}], markers:[{key, name, category, latest, series}] }`. `protocolBeforeAfter(dv, key, itemId)` → `{ before:{mean,n}, after:{mean,n}, delta }`.
- `lowerIsBetter` is `true`, `false` or `null` (in range is what matters). No optimal ranges are defined: `flag` is `'high'|'low'|null` from the report's `refLow`/`refHigh`, falling back to the report's own flag when a marker has no range. Values like `'<0.5'` parse to 0.5 (`qualifier: '<'`). `markerSeries` adds `qualifier, panelId`. `panelFlags` → `[{key, name, value, unit, refLow, refHigh, flag}]`. `labSummary.latest` = `{id, date, lab, markerCount, flaggedCount}` (null without panels); `changes` compare the latest panel with each marker's previous value, sorted by |pct| (1 decimal). `protocolBeforeAfter`: start = `startedAt` or first dose, "after" stops at `endedAt`; extra `pct, start`. Also exported: `parseValue, markerFlag, markerKey`.

## schedule.js
`planVsActual(dv, date)` → `{ blocks, plannedMin, doneMin, adherence, byCategory }`. `timeAllocation(dv, from, to)` → `[{category, plannedMin, doneMin}]`. `calendarLoad(dv, date)` → `{ meetingMin, count, afterHoursMin, backToBack, longestFreeBlockMin, fragmentation, firstStart, lastEnd }`. `timingTargets(dv, from, to)` → `[{key, label, target, avgActual, hitRate, n}]` for wake, bedtime, caffeine, lastMeal. `suggestDay(dv, date)` → `{ blocks:[{start, end, title, category, reason}], notes:[] }` (recovery-aware draft from the day template + readiness + calendar events; never overlaps events).
- `planVsActual.blocks` = `[{id, start, end, title, category, status, min, doneMin}]`; `byCategory` = `[{category, plannedMin, doneMin}]`; done minutes are null for future dates.
- `calendarLoad`: extra `connected` and `events: [{id, title, start, end}]`; all values null when no calendar is connected. `meetingMin` = union of event time; `afterHoursMin` = outside 08:00–18:00; `backToBack` = events starting ≤ 5 min after the previous one ends; `longestFreeBlockMin` within 08:00–18:00; `fragmentation` = share (0–1) of free 08:00–18:00 time in gaps shorter than 60 min; `firstStart`/`lastEnd` 'HH:MM'.
- `timingTargets`: `target` and `avgActual` in minutes after midnight (bedtime continuous past midnight), plus `targetHm`/`avgHm` strings; `hitRate` = % of days at or before the target.
- `suggestDay`: starts from the most recently edited `day` template, else blocks that appear in at least half of the last 4 same-weekday plans; in `recover` mode training blocks become 'Zone 2 / mobility' (category `recovery`, 30–40 min); blocks overlapping events are shortened to the largest free part (kept if ≥ 30 min and ≥ half the block) or dropped with a note; a `Deep work` block is added at `readiness.focus` when that window is free. Extra fields `date, basis: 'template'|'history'|null, mode`.

## correlations.js
`BEHAVIORS` / `OUTCOMES` catalogs. `findDrivers(daily, {minN=21, maxQ=0.1})` → `[{ behavior, outcome, method:'spearman'|'welch', effect, effectText, n, p, q, direction:'helps'|'hurts', strength:'weak'|'moderate'|'strong', sentence }]` sorted by strength; Benjamini–Hochberg across all tested pairs; associations only, phrased as such. `dataSufficiency(daily)` → `{ days, pairedDays, readyAt, message }`.
- Behaviors: `lastMealToBedMin, lastMealMin, caffeineLastMin, alcohol (binary), bedtimeMin, lateWorkout (binary: workout ending after 19:30), dayStrain, kcalIn, proteinG, carbsG, deepWorkH, meetingMin, afterHoursMeetingMin, daysSinceDose, sleepMin`. Outcomes: `nextRecovery, nextHrv, nextRhr (lower is better), nextSleepMin, nextSleepPerf, nextEnergy, deepWorkH, executionScore` (same-day ones are only paired with meetings, bedtime/sleep and days since dose; trivial pairs are skipped). Night behaviors (`bedtimeMin`, `sleepMin`) describe the night that ended on the row's date, so they are paired with the next row for next-morning/next-night outcomes.
- **Stratified by day type** (option `stratify = true`): tests run within weekday and weekend strata (next-morning outcomes use the evening's type: Fri/Sat nights are weekend) and are pooled — Spearman via Fisher z (weights n−3), binary via a sample-size-weighted mean difference with Satterthwaite df (= Welch with one stratum) — so day-of-week habits do not show up as drivers.
- Minimum n = `minN` paired days (binary: also ≥ 7 days per group); kept when q ≤ `maxQ` and |rho| ≥ 0.2 or |d| ≥ 0.3 (strength 0.2/0.35/0.5 and 0.3/0.5/0.8). `effect` is in outcome units: binary = with − without; continuous = high group − low group, split at the (rounded) median (or any-vs-none). `direction` is from the behavior's high/present group's point of view. Extra fields: `rho, d, stratified, threshold: {value, op}|null, groups: {hi: {n, mean}, lo: {n, mean}}`. Example sentence: "Nights with your last meal ≥3h before bed are associated with +6 ms HRV next morning (n=34, q=0.04)."
- `dataSufficiency` also returns `minN`; `readyAt` = the date the `minN`-th paired day was logged, or the projected date when not yet ready.

## weekly.js
`weekStats(dv, weekStart)` → `{ week, from, to, daysLogged, averages, deltas, best, worst, perfectDays, training:{sessions, sets, prs}, weightChange, adherence:{protein, kcal, stack}, highlights:[string], focusCandidates:[{key, text, reason}] }`.
- Any date normalizes to its Monday. `week` = ISO week label ('2026-W39'); `from`/`to` = Monday/Sunday; extra `complete`; days after today are excluded. `averages`/`deltas` (vs the previous week) cover recovery, hrv, rhr, sleepMin, sleepNeedMin, sleepPerf, dayStrain, kcalIn, proteinG, executionScore, deepWorkH, planAdherence, energy, meetingMin, weightTrendLb. `best`/`worst` = `{date, executionScore, recovery}`. `training.prs` is a count (`training.prList` has the PRs). `adherence` values are percentages (`stack` = supplement doses taken / due). `focusCandidates` (max 5) carry a 0–1 `gap` and are sorted by it (ties: sleep, protein, intake, weight, plan, driver); keys: `sleep, protein, intake, weight, plan, driver:<behavior>:<outcome>`.

## finance.js
`equityFor(gross, finance)` = max(0, (gross − expense) × 12 × mult × stake/100). `netWorth(snapshot, finance)` → `{ total, equity, assets, liabilities, byCategory }`. `netWorthSeries(dv)` → `[{month, total, equity, assets, liabilities}]`. `financeSummary(dv)` → `{ latest, previous, delta, series }`.
- `equityFor` is null when gross is unknown. `total` = assets − liabilities + equity; `byCategory` sums item values by category with liabilities negative. `financeSummary.latest`/`previous` = `{month, gross, ...netWorth}`; `delta` = change in total.

## context.js
`contextPack(dv, date, {days=30, includeJournal=false})` → markdown string for AI prompts: a CSV of key DailyRow columns, targets, active standards, protocol items (use `neutralLabel` when set), latest lab flags. Never includes tokens, keys or journal text unless asked.
- `date` defaults to `dv.asOf()`. Sections: goals & targets, daily CSV (`date,rec,hrv,rhr,sleep_h,bed,strain,kcal,prot_g,meal_bed_h,train,wt_trend,exec,deep_h,meet_h,dose_d,alc,energy`), readiness, standards (14-day adherence), protocol items (neutralLabel hides both name and kind), strength, latest lab flags and changes, top associations (90 days), journal (only with `includeJournal`). About 5k characters for 30 days.
